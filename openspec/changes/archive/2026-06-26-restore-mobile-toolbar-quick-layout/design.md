## Context

`refine-mobile-command-controls` 将移动端工具栏压缩成单行,固定快捷键横向滚动,系统操作大多进入设置/更多菜单。该方向减少了高度,但用户反馈手机端需要更“快速直接”:默认就能看到老版本式的多行快捷操作,尤其是编辑、展开、设置和两行固定快捷键。同时当前 Composer 草稿入口是打开动作但缺少显式面板可见状态,重复点击或焦点切换后可能出现 Composer 模式已开但 textarea 不可见/不可聚焦的体验。

## Goals / Non-Goals

**Goals:**
- 移动端默认展示三行快速工具栏:系统快速操作一行,固定快捷键两行。
- 第一行保留设置/更多、编辑快捷键、展开/收起、Composer 草稿和 Attention badge 等高价值入口。
- 固定快捷键按用户配置顺序显示,默认可直接点,不完全藏到设置菜单。
- 修复连续点击草稿入口导致输入框不可见的问题,让草稿入口成为幂等打开/聚焦动作。
- 保持桌面端和嵌入侧边栏工具栏行为不变。

**Non-Goals:**
- 不恢复常驻 `直连 / 草稿` 分段控件。
- 不改变 SQLite、输入历史、草稿持久化或 Attention 后端 API。
- 不重做快捷键编辑器或预设推荐逻辑。

## Decisions

### D1. 移动端采用三行默认布局

**选择**:移动端正常工具栏使用固定三段:
1. 系统快速操作行。
2. 固定快捷键第一行。
3. 固定快捷键第二行。

固定快捷键按用户配置顺序切分成两行,每行在横向空间不足时保持单行横向滚动。

**理由**:这符合用户“默认展示老版本三栏/一栏设置按钮、另外两栏固定行快捷键”的反馈,比单行滚动更直接。

### D2. 设置菜单保留低频操作,但不隐藏快速入口

**选择**:设置/更多菜单仍包含低频操作,但编辑快捷键、展开/收起、Composer 入口这类快速动作也在第一行可见。

**理由**:移动端工具栏的主要价值是减少点按层级。用户明确要求“快速展开、编辑”等要快速直接。

### D3. Composer 入口改为显式 open/focus

**选择**:`openComposer` 始终设置 `composerMode='composer'`,强制标记面板可见,并在下一个 frame 聚焦 textarea。重复点击只重新聚焦,不切换关闭。关闭只由面板关闭按钮或菜单 Direct 操作触发。

**理由**:草稿入口的心理模型是“打开/回到草稿”,不是 toggle。幂等打开可以避免多点两次后面板消失。

## Risks / Trade-offs

- **三行占用更多高度** -> 接受该权衡,因为用户明确优先快速直接;Composer 面板仍按需展示,不恢复常驻分段行。
- **固定快捷键过多** -> 每行保持稳定高度并横向滚动,不换行撑高。
- **重复点击焦点时序** -> 使用 requestAnimationFrame/setTimeout 聚焦 textarea,并在无草稿时也保持 Composer 模式直到显式关闭。

## Migration Plan

1. 更新 OpenSpec delta spec 和任务。
2. 调整 `Toolbar.tsx` 移动端布局为三行。
3. 调整 `Terminal.tsx` Composer 打开/关闭状态,修复重复点击。
4. 运行 build 和现有快捷键测试。
5. 重启 `nexus` 服务并验证可访问。
