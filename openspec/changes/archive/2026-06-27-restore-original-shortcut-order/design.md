## Context

当前移动端工具栏已经恢复为三行:第一行系统快速操作,第二/第三行固定快捷键。但实现上仍有三个与用户预期不一致的点:

- 第一行系统按钮从左侧开始排列,设置/更多按钮不在靠右位置。
- 自定义快捷键新增时默认进入展开区,需要额外操作才能进入固定区。
- 固定区展示按当前配置拆分,但需要明确以最开始的默认固定快捷键顺序为基准,自定义键只能追加在固定区末尾,不能插入或挤乱默认键。

## Goals / Non-Goals

**Goals:**

- 恢复移动端默认固定快捷键的原始顺序和位置体验。
- 新增自定义快捷键默认追加到固定区末尾。
- 移动端第一行系统快速操作保留直接触达,但设置/更多入口靠右显示。
- 保持三行默认布局:第一行系统快速操作,第二/第三行固定快捷键。
- 保持 Composer 草稿入口幂等打开/聚焦逻辑不变。

**Non-Goals:**

- 不恢复常驻 `直连 / 草稿` 分段控件。
- 不重新设计快捷键编辑器的拖拽交互。
- 不改变 PC 工具栏和 embedded 侧边栏工具栏的排列。
- 不移除用户保存的现有配置;只调整默认/新增行为和移动端展示规则。

## Decisions

### D1. 固定区默认顺序以 `FACTORY_CONFIG.pinned` 为基准

移动端默认固定键 SHALL 使用出厂默认固定键顺序。实现时应核对 `toolbarDefaults.ts` 中的 `FACTORY_PINNED` 是否代表“最开始”的默认位置,并避免在移动端渲染时重新按系统按钮或分类排序固定键。

理由:用户强调“最最开始的默认快捷键位置”,因此默认固定区应该来自单一权威配置,而不是被移动端布局逻辑重排。

### D2. 自定义快捷键默认追加到固定区末尾

`addCustomKey()` 创建自定义键后 SHALL 将新 key id 追加到 `config.pinned` 末尾,保留 `config.expanded` 不变。用户仍可通过编辑器把它移到展开区或删除。

理由:用户明确需要“自定义快捷键是加在默认快捷键固定区的末位”。追加而非插入可以保证默认键相对顺序不被破坏。

### D3. 移动端第一行采用左右分组

移动端第一行 SHALL 使用左侧快速操作组和右侧设置/更多按钮。编辑、展开/收起、Composer 草稿、Attention 位于左侧或中间快速操作组;设置/更多按钮使用 `margin-left:auto` 或等效布局靠右。

理由:设置是低频入口,靠右符合用户反馈和常见移动工具栏布局;高频操作仍直接可点。

### D4. 两行固定键按固定区顺序平均拆分

第二、第三行 SHALL 继续从 `config.pinned` 顺序切分展示。新增自定义键追加到 `config.pinned` 后自然出现在固定区末尾;如果空间不足,每行横向滚动,不换行撑高。

理由:保持三行高度稳定,同时满足“另外两栏是默认固定行快捷键”。

## Risks / Trade-offs

- **已有用户配置可能已经把自定义键放在展开区** → 不自动迁移历史配置,避免违背用户手动整理;只改变新增自定义键的默认目标。
- **固定键数量变多后末尾键可能需要横向滚动** → 保持单行横向滚动,不破坏三行稳定高度。
- **设置靠右后菜单定位需要更新** → 继续使用按钮/toolbar 尺寸计算菜单位置,必要时用右侧偏移确保菜单不出屏。
- **“最开始默认顺序”定义不清** → 以当前代码中的 `FACTORY_CONFIG.pinned` 作为权威默认;如历史版本另有顺序,实现时通过 git 历史核对后调整常量。
